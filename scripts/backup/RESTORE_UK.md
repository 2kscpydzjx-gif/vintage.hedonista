# Відновлення Vintazhka з копії

Спочатку виконати на окремому середовищі. Цей пакет автоматично повертає файли й перевіряє цілісність, але не виконує імпорт у робочу базу. Повне відновлення потребує перевірки сумісності Supabase та налаштування зовнішніх сервісів.

## Отримання зашифрованої копії

Потрібні доступ до приватної папки Google Drive, правильний пароль Restic та ID репозиторію. Внести їх локально у змінні середовища `BACKUP_DRIVE_TOKEN`, `RESTIC_PASSWORD`, `BACKUP_REPOSITORY_ID`, не в історію команд із буквальними паролями.

Встановити перевірені інструменти з `install_tools.py`. Програма орієнтована на Linux x86_64; у Windows можна використовувати WSL. Отримати ID знімка з приватної історії Actions або командою Restic snapshots з відповідною конфігурацією.

```
python3 scripts/backup/run.py restore-files --snapshot SNAPSHOT_ID --output /private/path/empty-restored-copy
```

Папка призначення має бути новою або порожньою. Програма відновить знімок і перевірить SHA-256 кожного файлу. У папці будуть `database/`, `media/`, `code/`, `deployed-functions/` та `manifest.json`. Папка міститиме конфіденційні розшифровані дані; не завантажувати її у публічний GitHub, у відкриті артефакти або публічну папку Drive.

## Підготовка окремого середовища

1. Визначити цільовий Supabase або локальний стек, сумісний із джерелом PostgreSQL 17, Auth і Storage. Створення платного ресурсу потребує окремого погодження.
2. Перевірити необхідні PostgreSQL-розширення, Database Webhooks і ролі. `schema.sql` фіксує прикладну схему, політики, функції та тригери; `roles.sql` не містить паролів власних LOGIN-ролей.
3. Порівняти `auth-storage-reference.sql` зі стандартною схемою нового проєкту. Застосувати лише власні потрібні зміни Auth/Storage, зокрема тригери та RLS-політики. Не імпортувати весь довідковий файл поверх керованих схем навмання.
4. Перевірити й замінити старий project ref `yffwjgwwkapdrpwyjwfp` у власних SQL-функціях, URL фотографій і конфігурації сайту на новий. Зберегти оригінал копії без змін.

## База

Офіційний порядок: `roles.sql`, `schema.sql`, `data.sql`, потім `history-schema.sql` та `history-data.sql`. Імпорт виконувати через `psql --single-transaction --variable ON_ERROR_STOP=1` з `SET session_replication_role = replica` перед даними, за актуальною інструкцією Supabase. Потрібні права на цей параметр і сумісна версія `psql`.

Не включати листи/Telegram при перевірці: після імпорту в тестовій базі залишити `zz_vh_order_email_webhook` та відповідні Telegram-тригери вимкненими, перш ніж дозволяти будь-які тестові записи. Усі зовнішні адреси й ключі тестового середовища потрібно ізолювати.

`vh_order_email_webhook_secret` з Vault не вважати переносним зашифрованим значенням. У новому проєкті створити новий внутрішній секрет через перевірену міграцію/окремий узгоджений bootstrap. Перевірити URL `resend-email` у функції черги, права hash-RPC, `verify_jwt` і конфігурацію обох поштових функцій. Ключі не друкувати.

## Файли та функції

1. Відновити bucket `vintage-media`, його доступи та обмеження. Файли знаходяться у `media/vintage-media/`; локальний `media/inventory.json` — службовий маніфест, не завантажувати його як об'єкт Storage.
2. Завантажити файли з початковими ключами через S3/API нового проєкту, звірити кількість і контрольні суми.
3. В `deployed-functions/` збережені джерела та інвентаризація розгорнутих функцій; у `code/repository.tar.gz` — код сайту, міграції й конфігурації з відповідного коміту. Перевірити `deno.json`, import maps та `verify_jwt`, оскільки завантаження функцій CLI може не включати всі налаштування залежностей.
4. Окремо внести нові або збережені секрети Resend/Telegram/Cloudflare та інші змінні. Їх значення не повертаються звичайним дампом.
5. Налаштувати Auth Site URL/Redirect URLs, SMTP/OAuth, Realtime publications, домен і DNS. Дамп бази не відновлює ці зовнішні налаштування автоматично.

## Що звірити

- Кількість і вибірковий вміст товарів: ціни, заміри, описи, зв'язки, наявність.
- CMS-чернетки та опубліковані сторінки, меню й фотографії.
- Замовлення й рядки замовлень, ролі адмінів і доступи RLS.
- Наявність Auth-користувачів та контрольний вхід без надсилання листів справжнім покупцям.
- Усі файли Storage, залежності Edge Functions і відсутність випадкових сповіщень.

Лише після успішного імпорту та цих перевірок зафіксувати результат, тривалість відновлення й `BACKUP_RESTORE_VERIFIED=true`. До цього автоматичне видалення старих копій залишається вимкненим. Перемикання робочого домену й відновлення у робочий проєкт потребують окремого узгодженого вікна; дружина не повинна одночасно редагувати товари в базі, яку відновлюють.

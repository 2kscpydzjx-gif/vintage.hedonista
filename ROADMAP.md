# Vintage Hedonista — робочий план

Оновлено: 19 жовтня 2026. Цей файл — єдине місце для плану; оновлювати після завершення кожного етапу.

## Принципи
- Один обмежений PR на одну проблему, перевірка CI, ручне тестування до merge.
- Не змінювати без окремого погодження затверджений дизайн каталогу, фільтри, картки товарів і checkout.
- Не видаляти старі блоки/дані без інвентаризації, резервної копії та перевірки сторінок, що їх використовують.
- Пріоритет: стабільне додавання товарів і продажі, а не нескінченне SEO-полірування.

## Етапи

### 1. Короткий SEO-аудит категорій — орієнтир 2–4 години
- [ ] Перевірити title, meta description, H1, canonical категорій та підкатегорій.
- [ ] Виправити тільки суттєві проблеми, окремим PR.
- [ ] Статус sitemap у Google Search Console перевірити пізніше: XML доступний, але Search Console повідомляв про помилку обробки.

### 2. Інвентаризація та безпечне прибирання конфліктів V1/V2 — на початку стабілізації адмінки
- [ ] Знайти всі старі рендерери, редактори, CSS, схеми блоків, локальні та Supabase-джерела даних.
- [ ] Скласти таблицю: активний V2 / сумісність / застарілий код / ще використовується.
- [ ] Зробити резервну копію структури й даних блоків та зафіксувати поточний вигляд сторінок.
- [ ] Налаштувати єдине джерело даних і один рендерер, прибрати мерехтіння та повторну появу старих блоків.
- [ ] Після перевірки мігрувати потрібні старі блоки, вимкнути legacy-шляхи; фізично видаляти код тільки окремим PR.
- [ ] Регресія: Home, Catalog, Product, Journal, About, Contacts, Delivery, Capsules/Styles, Desktop/Mobile.

### 3. Стабілізація адмінки V2 — орієнтир 1–3 робочі дні
- [ ] Автозбереження, збереження після F5, публікація, залишатися на тій самій сторінці.
- [ ] Без мерехтіння фото; правильні реальні прев'ю й мініатюри.
- [ ] Кадрування/переміщення/масштаб, ширина фото й тексту, позиціонування блоків.
- [ ] Прибрати лаги та дубльовані редактори; перевірити роботу з товарами.

### 4. Капсули та обробка замовлень — орієнтир 2–4 робочі дні
- [ ] Перевірити зв'язки look → products, кількість, статус і доступність речей.
- [ ] Додавання вибраних товарів із капсули в кошик без дублювання.
- [ ] Правильна ціна, склад замовлення, дані в checkout та в адмінці.
- [ ] Перевірити резервування/продаж одиничних речей, мобільний сценарій.

### 5. Легкі корекції дизайну — орієнтир 0,5–2 робочі дні
- [ ] Відступи, типографіка, розміри фото, адаптивність — тільки узгоджені точкові зміни.
- [ ] Не переробляти затверджені макети.

### 6. Фінальне тестування — орієнтир 1–2 робочі дні
- [ ] Товар → публікація → SEO → капсула → кошик → замовлення.
- [ ] Desktop/Mobile, консольні помилки, швидкість і стабільність.
- [ ] Повторна перевірка Search Console і sitemap.

## Оцінка
Загальний орієнтир: 2–3 тижні календарного часу за умови невеликих PR і регулярної перевірки. Це не гарантія; складні проблеми зі станом редактора, міграцією legacy-блоків чи замовленнями можуть змінити термін.

## Поточний наступний крок
Короткий SEO-аудит категорій, після нього одразу інвентаризація старих блоків та стабілізація V2. Капсули й замовлення — наступний функціональний пріоритет; косметичні правки можна виконувати окремо, без блокування продажів.

# Зрозумілі URL — тестова гілка

Нові публічні адреси Cloudflare:

- Товар: `/product/vovnyanyi-zhaket-kardyhan/`.
- Категорія: `/catalog/verkhnii-odyah/`.
- Підкатегорія: `/catalog/verkhnii-odyah/kimono/`.
- Стаття: `/journal/nazva-statti/`.

Поточні slug, товари, ціни, заміри й записи CMS не змінюються. Під час збірки Cloudflare копії SEO-сторінок отримують нові шляхи, а посилання, sitemap, canonical, Open Graph та JSON-LD посилаються на ті ж адреси. Вихідні папки `seo-*` залишаються сумісними з поточним плановим генератором; звичайна збірка для попереднього хостингу також підтримується.

`_redirects` забезпечує 301 для старих `seo-*` адрес з `index.html`, зі слешем і без нього. Параметри посилань зберігаються. Старі `product.html?slug=...` і `article.html?slug=...` продовжують працювати; після завантаження наявного товару/статті браузер оновлює адресу без повторного завантаження сторінки.

Точні 200-rewrite правила віддають готовий HTML існуючих сторінок. Фізичний файл товару має вигляд `product/slug.html`, а ціль proxy — `/product/slug` без розширення: публічна адреса `/product/slug/` залишається в браузері. Цілі з `index.html` Cloudflare відхиляє як цикл; proxy на `product.html` запускає нормалізацію HTML і губить slug. Тому жодна 200-ціль не містить `.html`. Загальні правила наприкінці файлу відкривають щойно опубліковані товари, статті та категорії через поточні шаблони ще до наступного створення SEO-знімків. Файли шаблонів і вкладені сторінки використовують базову адресу поточного хоста, тому навігація, фото, профіль і кошик не переходять на інший хост. Відсутній товар показує поточний стан «Товар не знайдено» з noindex; стороння невідома адреса повертає HTTP 404.

HTTP-тести використовують офіційний `unstable_generateASSETSBinding` із зафіксованого Wrangler 4.156.1 замість самописної імітації хостингу. Вони відхиляють будь-яке попередження парсера правил і вимагають прямої відповіді HTTP 200 для нових адрес.

Перевірки: усі наявні знімки та старі варіанти URL, збереження query-параметрів, початковий HTML, canonical/OG/JSON-LD, sitemap і внутрішні посилання; desktop/mobile каталог → товар → кошик → checkout; нові товари/статті/категорії без знімків; зміна категорій без пошкодження базової адреси; ізоляція записів тестового середовища. `tests/clean-urls.cjs` і `tests/cloudflare-pages.cjs` змінюють dist, тому їх запускають послідовно перед браузерними тестами, які лише читають збірку.

Зміни поки призначені лише для тестової гілки. Публікація на основному домені потребує окремої вказівки власника.
